RunbookPilot setup guide

How to get RunbookPilot running on a new laptop, from a fresh machine to the app open in your browser. Setup takes about 15–20 minutes, most of it installing tools.

1

Install the tools

One time only. After installing everything, close and reopen your terminal so it picks up the new tools.

ToolDownloadCheck it works
Gitgit-scm.comgit --version
Python 3.12python.orgpython --versionpython3 --version
Node.js 20+ (LTS)nodejs.orgnode --version
Docker Desktopdocker.comOpen it and wait for Engine running
Python on Windows: tick "Add Python to PATH" on the first screen of the installer.
2

Clone the repo

Open PowerShellTerminal and run:

cd $HOME\Documents
git clone https://github.com/SameerMatoria/RunBookPilot.git
cd RunBookPilot
cd ~/Documents
git clone https://github.com/SameerMatoria/RunBookPilot.git
cd RunBookPilot
3

Set up the backend

Creates a private Python environment and installs the backend's packages.

cd backend
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
copy .env.example .env
notepad .env
cd backend
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
open -e .env          # or: nano .env

In the file that opens, replace gsk_xxx with your Groq API key and save. Reuse your existing key or create one at console.groq.com/keys.

Why this step is manual: the .env file holds your secret key, so it is never uploaded to GitHub. You need to create it on every new machine.
4

Set up the web app

cd ..\frontend
npm install
cd ..
cd ../frontend
npm install
cd ..
5

Start RunbookPilot

Make sure Docker Desktop is running first.

From the RunBookPilot folder:

powershell -ExecutionPolicy Bypass -File .\start.ps1

This starts the database in Docker, then opens three windows (the backend, a worker that runs the AI agents, and the web app), then your browser at http://localhost:5173.

Use three terminal windows, all starting in the RunBookPilot folder.

Terminal 1: database + backend

docker compose up -d db
cd backend
.venv/bin/alembic upgrade head
.venv/bin/python -m uvicorn app.main:app --port 8000

Terminal 2: worker (runs the AI agents)

cd backend
.venv/bin/python -m app.worker

Terminal 3: web app

cd frontend
npm run dev

Then open http://localhost:5173.

Check: both dots in the top-right corner of the app should be green: the AI model and the sandbox.
6

Sign in

On a brand-new database the page offers Create the first admin: pick a username and a password of 8+ characters. That admin adds everyone else on the Users page and gives them roles: submitter (uploads runbooks), approver (approves scripts), operator (runs them on servers), admin.

Approving needs a second person. Nobody can approve a runbook they uploaded, so for a solo test create a second user with the approver role.
7

Do a first test run

Drag samples/restart-web-service.md onto the upload box, answer the questions, and let it run through to the review card.

Do this before any demo. The first sandbox test downloads and builds the sandbox, which adds 1–2 minutes. After that, each test takes seconds.

Optional: run it on a server

Start the demo server with docker compose up -d demo-server. On the Servers page add a password credential (user ops, password runbookpilot-demo), then a server with hostname localhost and port 2222, and click Test connection. Then open an approved runbook and use Run on servers.

Every time after that

  1. Open Docker Desktop and wait for Engine running.
  2. From the RunBookPilot folder, run powershell -ExecutionPolicy Bypass -File .\start.ps1
  3. Start the backend, the worker and the web app in three terminals, as in step 5.
  4. To stop, close the three PowerShell windowsterminals (or press Ctrl+C in each).

If something goes wrong

ProblemFix
python not foundReinstall Python with "Add Python to PATH" ticked, then reopen PowerShell.Use python3, or install Python 3.12 from python.org.
Script won't run: "running scripts is disabled"Use the full command from step 5, which includes -ExecutionPolicy Bypass.
Top-right shows Sandbox offlineDocker Desktop isn't running. Start it, wait for "Engine running", then refresh the page.
Top-right shows No worker running, or runbooks stay "Queued"The worker window was closed. Start it again: cd backend then .venv\Scripts\python -m app.worker.
First dot (AI model) is redThe key in backend/.env is missing or wrong. Fix it, then restart the backend.
"Port already in use"Another copy is already running. Close the old windows first.
An agent fails with "rate limit"You've hit Groq's free limit. Wait a minute, or add a free Gemini backup key in backend/.env.
Code was updated on GitHubRun git pull, then the install commands from steps 3 and 4 again.
